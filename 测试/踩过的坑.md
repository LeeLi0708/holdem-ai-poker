# 踩过的坑（详细版）

> 这是 `MEMORY.md` 里「反复踩过的坑」的完整版。
> MEMORY.md 只保留了每条的标题摘要 —— 需要细节时来这里查。
> 新增坑请在 `MEMORY.md` 加摘要，细节补到这里。

**1. 破坏性开关「光测一个入口不算测过」。** `resetMem(p)` 内部写 `p.mem.notes`，三个调用点却传 `p.mem`
→ TypeError →「清空所有/在座/她的 AI 记忆」三条路径**全部当场中断**，界面上却像清了；老自检 562 项全绿
也没发现（**只测过 `wipeSeatsMem`**，那条碰巧是好的）。
**2. 断言不能只看它绿，还得看它有没有真的在测东西。** 改口径时必须**同时补一条「确认那件事真的发生了」**，
否则空数组让 `every()` 恒真 → 假通过。（`B4 读牌不跨人` 就栽过。）
**3. 测试自己不能跟游戏抢随机源。** 根因是**测试的 `act()` 也用 `Math.random`**，与游戏共用一源、
调用时机又是时间驱动轮询 → 消耗次数不定 → 牌序漂。改用轮次号派生。配套：`seedFromNow()` 刻意
**只从 Math.random 派生、不掺 Date.now()**。
**4. mock 与归类陷阱。** mock 的 `classify()` 只返回 `{kind,sys,usr}`，没有 `thinkOn` —— 判思考开关要从
`body.thinking` 读。`coachSys(role)` **第一行决定归类**（coach-hand 要含「逐手复盘」、coach-phase 要含
「阶段总结」），**写错会静默落到 coach-mem**。
**5. Python 补丁脚本里 JS 的换行转义要写四个反斜杠**（`\\n`），写两个会被解析成真实换行 → 语法错误。
**6. ⚠ Read 读这个大文件（1.3MB、含 16 行超长 base64）会静默丢行、行号漂移** —— 曾漏掉
`recordHandMemory()`/`reflectAll()` 末尾的 `saveRoster()`。**规矩：核对行号一律 `grep -n`/Python；
每段 ≤150 行；读完用锚点回验。**
**7. 断言 CSS 要取「最后一条生效的规则」。** 历史版本有三条时，`.exec` 拿到的是**第一条**（旧的），
用 `match` 取末位。⚠ 且**必须先剔掉 `@media` 块**（踩过两次；否则窄屏回落规则会被当成最后一条）。
**8. 无头截图本机完全不可用**（六种组合全部无输出）—— 核对渲染用 jsdom 读 DOM。**布局改动要用户实机看。**
**9. 「0 是合法值」的字段绝不能用 `||` 兜默认值。** `idOf` 的 `|| 1` 把 0 号座吞掉，你当庄时按钮位指错人。
PS 牌谱座位号一律 **1-based**（`seatNo(i)=i+1`，三处统一）。
**10. 档案是跨版本长期留存的东西，读取侧容错要做全。** `fixHist` 要把所有「渲染时直接取
`.length/.map`」的字段归一（revealed/showSay/acts/stacks/winners）。
**11. 新增请求 kind 要同步三张表**：CSS 徽章 / 日志筛选下拉 / `KIND_CN`。已做成 `allKinds()` 全量对照断言。
**12. 恢复备份后必须 `reloadAllData()`** —— 写盘 ≠ 界面已刷新。localStorage 键统一进 `BACKUP_KEYS`。
**13. 比牌/胜率这类口径必须先定清楚再算。** 补牌要分「成牌补牌（顺子及以上）」与「能升一档的牌」，
后者含「变成一对」→ 同花听牌被算成 23 张、4/2 法则估出 46%。**一个好听但错的数字，比两个朴实的好。**
**14. ⚠ Windows 的 `.bat` 必须存成 GBK + CRLF（内部再 `chcp 936`）。**
cmd.exe 的行读取按 CR 走，**整份只有 LF 时会把相邻行拼错**：`if not exist` 被拆出 `not`、
`echo` 被拆成 `cho`/`o`、`END` 被拆成 `nd`，`goto` 还会跳飞 —— 报「不是内部或外部命令」，
看着像命令拼错了，其实是行尾错了。**实测：只把编码改成 GBK、行尾仍 LF，照样错 3 处 → 行尾才是主因。**
另：UTF-8 + `chcp 65001` 看着能跑，但带 `if ( )` 多行块时**吞过一行 `echo`**，不稳定，别用。
→ **Write 类工具默认写 LF**，所以 `.bat` 一律用 Python 按 `'\\r\\n'.join(...).encode('gbk')` 写盘；
改完先跑 `测试/检查bat编码.py`（一秒，正负两向都验过）。
**15. ⚠⚠ 构造不出被测场景的测试，比「没有测试」更危险 —— 它会假红，更会假绿。**
第二十一轮补丁 B（音频未解锁时闸门立刻放行）写完后，自检 3f 一直红。当时差点去改主文件，
先写探针把中间状态打出来，才发现**两个假象叠在一起**：
① 报的「156ms 内放行」里 **150ms 是测试自己的 `await sleep(150)`**，`open6` 其实是 `false` ——
   闸门压根没放行，「放行」是看差了；
② `locked` 恒为 0，因为**补丁 B 根本没被走到**：`ttsSetOn(false)` 只清 `TTS.ctx`、**不清 `SFX.ctx`**，
   重开时 `ttsCtx()` 又复用了那个**在 unlocked 时创建、state 一直是 `running` 的旧实例**。
**真实浏览器里 AudioContext 一旦建好就一直活着** —— 在同一个页面里「加锁」**模拟不出**
「页面从没被解锁」这个前态。
→ 改法：**3f 单开一个页面，把 `lock(true)` 抢在任何 ctx 创建之前**，立刻绿（`locked=1`，放行 <10ms）。
→ 规矩：断言「某条分支会走到」之前，先确认**测试真的构造出了那条分支的前置状态**；
  凡「状态必须在对象建好之前就位」的场景，**必须新开一个干净的载体**，别在旧对象上原地改。
**16. ⚠ 测试要模拟真实的「打开 / 播完」时机，否则测的不是你以为的东西。** 第二十二轮一口气踩了三个：
① **假件不肯「播完」**：可控 AudioContext **故意不自动触发 `onended`**（不然「播完之前不许推进」
   就测不出来）。结果多句场景里第一句占着 `TTS.busy`，后两句永远发不出去，断言「三句都发去合成了」
   必红 —— **不是产品错，是假件不肯收尾**。修法：测试里手动逐句 `AUDIO.ended()` 放行。
② **控件是「打开面板那一刻」才回填的**：`writeGameCfgForm()` 只在 `openAISet()` 里调用，
   页面刚加载完控件还是 HTML 初始值。断言「跨页面后控件值对不对」必须先点一下设置按钮 ——
   **否则测的是 HTML 默认值，不是状态**。
③ **入口截断 ≠ 数据层守住**：开关的上限只写在「模型输出入口」（`takeMind`）时，
   绕过入口直接塞数据就绕过了开关。那条红断言反而暴露了设计漏洞 → 补上消费端兜底。
   **约束要放在「不管从哪条路进来都算数」的地方。**

**17. ⚠ 「报告成功」≠「真的写盘」—— 换音色时又栽了一次。** 第二十三轮：
换掉 `音色参考/liyi.wav` 后重跑 `准备音色.py`，它一路 `⏭ 已注册，跳过`，
最后还打印「音色表已写入 spk2info.pt」—— **看着全对，其实一个字都没写**
（`spk2info.pt` 的 mtime 一动不动，还是几小时前的）。差点据此得出「真人不比合成强」的错误结论。
根因：`if spk in have: continue` 只判断「**名字**注册过没有」，
不代表注册的是「**现在这个**参考音频」。换文件不触发重新注册，而且**根本没有参数能强制重来**。
→ 补 `--rereg`。**验证要找独立旁证**：改完后 `spk2info.pt` 从 686,328 B → 701,816 B
——体积变了才是真写进去了。**光看日志那行「✅ 已落盘」会被骗。**（同第十三轮「以为存了其实没写盘」。）

**18. ⚠ 「19 GB」常常是「整个包的体积」，不是「你需要的体积」。** 第二十三轮找真人音色：
完整包 19 GB，实测 OpenSLR 主站 **0.2 MB/s（要下 24 小时）**、EU 镜像 0.12、CN 镜像几乎不动，
8 路并发也没用（总带宽本身就卡在 0.2）。**换个思路就完全不同**：
① `spk-info.txt`（元数据）就在压缩包**最前面** → 前 5 MB 就能拿到全部 218 人的性别/年龄/口音；
② 目录顺序 `test/` 在前，而 test 集自己就有 **214 个说话人 / 172 个女声 / 全带转写**；
③ ModelScope 的 `/repo/tree` 能单查一个说话人的**每个文件大小**，
   而 44.1kHz/16bit/单声道 = **每秒 88200 字节** → **大小 ÷ 88200 = 时长**，不下载就能筛时长。
→ 最终只下了 **7 条音频（几 MB）**，走 ModelScope 单文件接口 **3 MB/s（快 15 倍）**。
**规矩：下大数据集之前先问两句 ——「我到底需要里面哪几条？」「有没有按需取的接口？」**
接口备忘：文件树 `/api/v1/datasets/{ns}/{name}/repo/tree?Revision=master&Root=`，
单文件 `/repo?Revision=master&FilePath=`；**`/repo/files` 会报「参数错误」，别用那个。**

**20. ⚠⚠ 加参数就要重算缓存键 —— 少一项不是「慢一点」，是「换个设置听到的还是旧声音」。** 2026-10-02 第二十四轮（演技：口气 + 语速）一口气踩了四条：

- **页面侧键漏了语速**：`ttsRun` 的键是 `key+tone+text`，**没有 rate**。
  拖完语速滑块，之前缓存过的句子照样按旧语速重放 —— 用户会以为滑块坏了。
  ⇒ 统一成一个 `ttsCk(key, tone, rate, text)`，**所有地方都走它**。
- **预热那句「已经缓存过就跳过」还在用旧键格式**（`key+text`），加了口气/语速后永远对不上
  → 每次点预热都白合成 7 句。**同一个键有两处使用，改一处就漏一处。**
  ⇒ 建键函数**导出给自检共用**，两边别再各拼各的。
- **服务端键漏了 speed**（原始的 `(backend,key,text,rate,pitch)`）→ 一并补上 `instruct` 和 `speed`。
- **⚠ 别拿「变慢/变快」去做小阈值断言**：CosyVoice 的**时长是随机采样**的，同一句两次能差 30%。
  我断言「慢悠悠比基线长 10%」→ 只 +7% 假红，**差点去改主文件**。
  ⇒ 拿**两个方向相反**的口气互比（急促 2.1s vs 慢悠悠 4.8s，差 2.25 倍），
  或把滑块区间拉宽（0.6 vs 1.6，差 3 倍）。**信噪比不够的断言，等于没有断言。**
- **⚠ 自检别依赖缓存冷热**：「第一次必是 cache=miss」第一次跑绿、第二次跑就红（缓存被捂热了）。
  ⇒ 要验「服务真调了引擎」，就**造一句从没合成过的话**（带时间戳尾缀）单独验；
  其余断言只比**相对差异**，不比缓存状态。

> 一句话：**「缓存键」是这个项目里最容易漏的地方** —— 每加一个会影响音频输出的参数，
> 都要问一遍「它进键了吗？键有几处在建？」。第十九轮、第二十二轮、第二十四轮各栽一次。

**25. ⚠⚠ 副语言标记能不能用，得跑真链路验，不能靠读代码猜 —— 顺手挖出「破折号会被吃掉」。** 2026-10-02（副语言标记 + 标点即语气）：

- 要给台词加 `[laughter]` / `[sigh]` / `[breath]`，先得回答「它能不能活着走到模型」。
  文本进模型前要过 `text_normalize` 一整条链：wetext 归一化 → `replace_blank` → `replace_corner_mark`
  → `.` 换 `。` → `remove_bracket` → `split_paragraph`。**任何一环吃掉它，写进台词就是白写。**
- 读源码先看到 `remove_bracket()` **只删全角 `（）【】` 和反引号**，方括号没事 ——
  但那是「读代码猜」，真凶更可能是 wetext。⇒ **跑一遍真链路才敢下结论**
  （`测试/_probe副语言标记.py`，纯 CPU、不用起服务）：标记**原样活到切句之后**，全绿。
- ⚠ **顺手挖到的真坑**：`remove_bracket` 里 `text.replace("——", " ")` 跑在 **`replace_blank` 之后**，
  所以破折号不是「消失」，而是**变成一个半角空格**。⇒ 提示词里**明令禁用破折号**：
  写「一百块——不」的人以为在拖长音，实际只断出个空格，还不如直接写 `……`。
  同理：全角 `（）` 会被整对删掉，连里面的字一起没。
- **白名单要跟 tokenizer 对表**：`[angry]` 这种不在册的方括号**不是音效，是被一个字一个字念出来的乱码**
  ⇒ 服务端 `clean_para()` 只放行 tokenizer 真注册过的那 12 个。
  探针把 `tokenizer.py` 里抓出来的注册表跟我们的白名单**互比**（12 = 12）——

**27. ⚠⚠ 裁静音把字一起吃了 —— 保留段的起点是 `s + keep//2`，不是 `s + drop//2`。** 2026-10-02（句内静音瘦身）：

- 背景：`slow` 口气会产出 1.8~2.9 秒的死空白（见 README「句内静音瘦身」），要后处理压短。
- 第一版写成：
  ```python
  drop = (e - s) - max_gap * sr
  a = s + drop // 2      # ❌ 起点该按「要保留多少」算，不是按「要裁掉多少」算
  b = a + drop           # ❌ b 越过段尾 e，把静音后面的**字一起裁掉**
  ```
  实测 9.60s 只省 2.55s —— **正确值应是 1.95s**，多省的 0.6 秒就是被吃掉的话。
- ✅ 正确：`a = s + keep//2; b = e - (keep - keep//2)`（`keep` = 要保留的长度）。
- ⚠⚠ **是「正向断言」抓出来的，不是「存在性断言」。** 若只测「有没有变短」，这一版是**绿的**。
  真正定案的是**守恒断言**：`非静音帧数必须一个不少`（248 → 248）。
  ⇒ **凡「删一部分、留一部分」的处理，「删对了」只能用守恒式断言证明，不能用「变化了」断言。**
  反向也必须要有：本来没有长静音的音频（`aimi_flat` 等 4 段）处理后**逐样本完全相同**，
  否则就是在动正常句子。

**29. ⚠⚠ 补丁脚本读文件必须 `newline=''` —— 否则 CRLF 被静默写成 LF。** 2026-10-02（下架 slow）：

- 本项目的铁律是「读时归一 LF、写盘还原 CRLF」，写法通常是：
  ```python
  src = io.open(path, encoding='utf-8').read()
  crlf = '\r\n' in src            # ← 这里恒为 False！
  text = src.replace('\r\n', '\n')
  ...
  io.open(path, 'w', encoding='utf-8', newline='').write(text.replace('\n', '\r\n') if crlf else text)
  ```
  **漏了 `newline=''`**：Python 默认的通用换行模式**在读的时候就把 `\r\n` 转成了 `\n`**，
  于是 `crlf` 检测恒假、`if crlf` 那支永不执行 → **整份文件从 CRLF 掉成 LF**。
- 最坑的地方是**它一路全绿**：锚点全部命中、打印的「已写盘」字节数只比预期小一点、
  语法检查通过、自检全过。**换行符这一层没有任何断言在看**，肉眼更看不出来。
  是「写盘字节数 1597571 vs 备份 1608539」这个 1 万多的差额露的马脚（差额 ≈ 行数）。
- ✅ **两处都要改**：`patch()` 里读 `src` 和预检里读 `text` 都得带 `newline=''`。
  并且**写盘后立刻回读验行尾**（`b'\r\n' in open(path,'rb').read()`），把这件事变成断言：
  ```python
  io.open(path, 'w', encoding='utf-8', newline='')      # 写：newline='' 表示不转换
  print('行尾 %s→%s' % ('CRLF' if crlf else 'LF', 'CRLF' if b'\r\n' in open(path,'rb').read() else 'LF'))
  ```
- ⚠ **回滚姿势**：改坏了别手改，直接从 `_backup_before_*.html` 覆盖回去，
  再用 `md5sum` 对着改动前记录核对（本轮 `4178c7bb…` / `7244d7cc…` 一比就确认回到了原点），
  然后**修脚本重跑**，而不是补一个「把 LF 转回 CRLF」的后处理 —— 那是把错误再盖一层。
- 📌 判定尺子：`CRLF 数 == LF 数 == CR 数` 才是纯 CRLF；三项不等就是混合行尾。
  本项目里 `德州扑克.html`、`server.py`、`README.md`、`踩过的坑.md`、`演技自检.js` 是 **CRLF**；
  `开口自检.js`、`赢牌发言自检.js`、`.workbuddy/memory/2026-10-02.md` 是 **LF**。
  ⚠ **别想当然「js 都是 LF」** —— 同一目录里两种都有，只能逐个查。

    改成按**每张图自己的背景绿主导度**反推过渡带宽与门槛。
  - ⚠ **全局"绿 > R+40"会打洞**：角色身上的绿色配饰会被一起抠掉。
    必须**从四条边 flood fill**，只抠与边框连通的背景；抠完再**补内部针孔**（从外泛洪找不到的透明区）。
  - ⚠ **边缘去绿（spill）要单做**：半透明像素 = 主体色×a + 背景绿×(1-a)，
    反解 a 之后把背景成分减掉，再把 G 压到 `max(R,G)`；不然贴到深色牌桌上有一圈荧光绿。
    （更正：是压到 `max(R,B)` —— 保留 R/B 里较大的那个，只削绿。）

**35. ⚠⚠⚠ 改了源码 ≠ 用户看到新东西 —— 名字存在**玩家本机的存档**里；而"剥注释"的测法本身也会假红。** 2026-10-02（改名后用户报「名字没改」）：

  **（一）产品侧：状态存在 localStorage 里，"源码级"断言全绿也没用。**
  - 7 位角色改名（`PROFILES` / `PERSONA` / 文档全换），自检 49 项全绿，用户截图**还是旧名**。
  - 根因：名字**存在玩家本机** `holdem_agents_v1` → `ROSTER.seats[].name`。
    `PROFILES` 只是**新存档的出厂值**；老存档一读回来就把旧名带回界面。
    ⇒ **只改源码、不迁移存档 = 改了等于没改。**
  - **为什么测试没抓到**：所有断言读的都是**新起的存档**（内存里 `defaultRoster()`），
    压根没走「老存档读盘」这条路。**测试和用户走的是两条不同的路。**
    📌 凡"改了一个用户看得见的值"，都要问：**这个值是每局现算的，还是存在存档里的？**
    存存档里的，**光改源码不算改** —— 要么迁移，要么写清楚怎么让用户重来一次。
  - 修法：代码里本有世代号机制 —— `loadRoster()` 见 `v < ROSTER_V`
    就把老座位整批请进替补席（`bench`，**记忆一分不丢**）、座位换新阵容。
    **`ROSTER_V: 2 → 3`** 即可。⚠ **名字再动必须跟着 +1。**
  - 补的测：`测试/_check改名迁移.js`（24 项，含"界面读数"与"跨一次页面加载"），
    并往 `ALLIN自检` 第六节补一段用 `v=ROSTER_V-1` 旧存档真跑。
    ⚠ 反向断言不能少：**当代存档（`v===ROSTER_V`）不许再迁移** ——
    否则一个"永远迁移"的 bug 也能全绿，而它会把玩家每局的阵容都重置掉。

  **（二）测试侧：两轮「假红」，都出在**剥注释**上。**
  断言「源码里旧名清零」时，我自己在 `ROSTER_V` 上方写了注释
  `// 第三十二轮把 7 位角色改名（李姨→墨千夜 …）` —— 于是这条**当场变红**。
  - ⚠ 但**注释里出现旧名是无害的**：不渲染、不进存档，反而是给后人的线索。
    断言该证的是「旧名不出现在**玩家看得见的地方**」，不是「全文一次都不许提」。
    ⇒ 先剥注释再数。**但剥注释本身踩了两个坑：**
  - **坑 A：HTML 不是 JS。** 第一版对**整份 HTML** 逐字符扫引号；
    1425 行的牌桌水印 `<div ...>TEXAS HOLD'EM</div>` 里那撇 `'`
    让扫描器以为进了字符串，之后每个 `'` 翻一次奇偶 —— 恰好到 `ROSTER_V` 那儿"假在串里"，
    注释没剥掉 ⇒ **假红（李姨×1）**。
    **修**：先在 HTML 里切出 `<script>` 段，再剥注释。
  - **坑 B：JS 正则字面量。** 第二版"逐字符状态机"把 `/[^\d]/` 的斜杠当**除法**，
    紧随其后的引号被误判成"字符串开始" ⇒ **又假红**。
    **修**：放弃"什么都能解析"的手写状态机 —— 它等于一个**不可靠的解析器**，
    在测试里只会制造假红。改用**朴素剥法**（块注释 regex + 逐行 `//`，先验该行引号配对）。
  - 📌📌 **假红比没有测试更危险**：它会诱导你去改**没坏的产品代码**。
    **断言红了，先怀疑测试，别急着改产品。**
  - 📌 附带一条读文件的常识：**Node `readFileSync(p,'utf8')` 的 `.length` 是"字符数"，不是"字节数"**
    （本文件 2069575 字符 / 2172315 字节，非 ASCII 多）。拿它跟 Python 的字节数比会**自以为文件被改坏了**。
    要字节数就 `fs.readFileSync(p)` 不加编码，或 `.length` 之前先 `.byteLength`。

## 36. ⚠⚠⚠ 「换代」要认**人**，不能认**版本号** —— 按世代号一刀切，会把同一个人劈成两半。

**报障（用户原话）**：「为什么被换下去了 **就是同一个人**」

**背景**：第三十二轮把这 7 位角色改名。名字（连同立绘、性格）存在**玩家本机的存档**里，
只改源码不生效 ⇒ 修法是 `ROSTER_V +1`，`loadRoster()` 见到 `v < ROSTER_V` 就重认一遍。

**错在哪**：迁移写成了「**老座位整批请进替补席**、座位换上 `defaultRoster()`」。
可改名时 **key 一个都没动**（`liyi`/`maiqi`/… 原样）——
**key 相同就是同一个人**，改名只该换名字。结果：
- 座位上是**新名字 + 空记忆**；
- 记忆全挂在**替补席的旧名字**上；
- 用户打开花名册一眼就看到「在座 7 个新人 ＋ 替补席 4 个旧名」。

**正解**：换代**按 `key` 认人**——
- 同 key ⇒ 留原座位、**记忆原封不动**，只更新名字 / 性格 / 立绘；
- key 在新阵容里已经没了 ⇒ 才进替补席；
- 同一个 key 出现**两份**（正是被劈开的存档：座位一份 + 替补席一份）⇒ **合并成一份**（并集）。
- ⚠ 合并的上限要跟主线一致（`notes ≤ 12` / `milestones ≤ 6` / `stats.recent ≤ 3` / `summary ≤ 400`），
  否则「修好了」的存档会在下一次写入时被主线的裁剪逻辑**悄悄削掉**。

**教训**：
- 📌📌 **判断「是不是同一个人」要用稳定标识（key），不能用「第几代」（版本号）**。
  版本号只说明「需要重认一遍」，**怎么认**才是关键。
- 📌📌 这条是**用户从界面上看出来的** —— 跑一万条「源码级」断言都不会红
  （断言跑的是新存档；**测试和用户走的是两条不同的路**）。
- 📌 **改了迁移口径，旧断言会集体失效**：`替补席里有 7 个旧名` 这条断言本身**就在描述那个 bug**。
  逐条问「这条还能证明那件事吗」，**改口径而不是删掉**。本轮改成：
  `替补席为空` ＋ `旧记忆留在座位上` ＋ 新增一节「已被劈开的存档要合并回一份」。
- 📌 新守卫必须**在打补丁前的备份上变红**（实测 16 项失败 / exit 1），否则不算验过。

## 第三十四轮（🎓 复盘角标「卡在 160」）2026-10-03

### 1. ⚠⚠ 「滚动窗口的长度」不是「累计数」—— 取错变量会让数字永远卡在上限
`updateCoachBadge()` 用 `COACH.hands.filter(r=>r.reviewed).length` 当累计数，
而 `fixCoach()` 会把 `COACH.hands` 裁到最近 160 条 ⇒ 角标到 160 就永远不动。
**真正的累计数 `COACH.stat.hands` 就在手边、还被面板标题行用着** —— 两处口径打架了很久没人发现。
📌 凡是「显示一个会增长的数字」，先问：**这个数是现算的窗口长度，还是真累计？**

### 2. ⚠⚠ JSDOM 不给 `url`，`localStorage.setItem` 会静默抛错 ⇒ 预置存档「测了个空气」
`new JSDOM(html, {...})` 默认 `about:blank`，是 opaque origin，写 localStorage 直接
SecurityError；而 boot() 里通常有 `try{...}catch(e){}` ⇒ **一点声音都没有**。
表现：断言全红、看起来像产品坏了，实际是**环境没搭起来**（比假绿更误导）。
**必须 `url: 'http://localhost/holdem'`**（`AI大脑自检.js` / `_check改名迁移.js` 都这么写）。

### 3. 插新行要跟源文件的 EOL 走
给 CRLF 文件插 LF 行 ⇒ `CRLF 数` 与 `LF 数` 不再相等（原行一行没坏，但文件变成混用）。
补丁脚本里统一做 `n.replace('\r\n','\n').replace('\n', EOL)`，EOL 由源文件探测。

### 4. 锚点别去数空格，用「行前缀 + 只在其后插一行」
注释里 `// 自检要验证 「160...` 中间多一个空格，整行锚点就命中 0 处。
改成按行匹配（`l.strip().startswith(...)`）并**保持原行不动**，插到它后面 —— 空格再也无所谓。

### 5. `slice(-0)` 就是 `slice(0)`（返回整份数组）
`past.slice(past.length - room)` 当 `room === 0` 时等于 `past.slice(-0)` = `slice(0)`
⇒ 该淘汰的历史一条没淘汰，防爆当场失效（160+50 变 210）。必须显式 `room > 0 ? ... : []`。
